# Documentar el contexto en GitHub

## Decisión

Centralizar el contexto del proyecto en un repositorio GitHub mediante documentos Markdown.

---

## Problema

A medida que aumentó la cantidad de roles, fue necesario explicar una y otra vez:

- El origen del proyecto.
- La visión.
- Las decisiones tomadas.
- Los aprendizajes obtenidos.

Cada incorporación requería repetir el mismo contexto.

---

## Solución

Crear una base de conocimiento compartida donde cada rol pueda leer el contexto antes de comenzar a trabajar.

La explicación deja de depender de una conversación y pasa a depender de documentación.

---

## Regla

> **Antes de incorporarse a un trabajo, cada rol debe leer el contexto obligatorio asociado.**

---

## Beneficios

- Todos comienzan con la misma visión y contexto.
- Se reducen reuniones de contexto y explicaciones repetidas.
- Evitar reinterpretaciones.
- El conocimiento queda disponible para futuros roles.
- El nuevo conocimiento puede agregarse sin modificar los archivos anteriores.
- Queda evidencia cronológica de cómo evolucionó la idea.

---

## Conclusión

GitHub deja de ser únicamente un repositorio de archivos.

Pasa a convertirse en la memoria compartida del proyecto y en el mecanismo de incorporación para todos los roles de LAPIN DIGITAL.
